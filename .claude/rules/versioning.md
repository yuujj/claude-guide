# 버전 관리 규칙

## 형식: MAJOR.MINOR.PATCH (예: 0.6.0)

| 자리 | 이름 | 변경 기준 |
|------|------|-----------|
| **MAJOR** | 메이저 | 새 페이지 추가, 내비게이션 구조 변경, 전체 디자인 시스템 교체 |
| **MINOR** | 마이너 | 새 섹션 추가, 기존 섹션 콘텐츠 대폭 보강, 새 컴포넌트·시나리오 추가 |
| **PATCH** | 패치 | 버그 수정, 오타·문구 교정, CSS 스타일 미세 조정, 접근성 개선 |

## 마일스톤 기준

| 버전 | 의미 |
|------|------|
| `v0.x.x` | 개발 단계 — 페이지 구축 진행 중 |
| `v1.0.0` | 콘텐츠 완성 기준점 — 4개 제품 페이지 + TIP 페이지 초안 완료 |
| `v2.0.0~` | 메이저 개편 시 |

## 배포(git push) 필수 절차

> git push 전 아래 3가지를 반드시 완료합니다.

### 1. `version.json` 업데이트
```json
{
  "version": "X.Y.Z",
  "date": "YYYY-MM-DD",
  "notes": "변경 내용 한 줄 요약"
}
```

### 2. `CHANGELOG.md` 최상단에 항목 추가
```markdown
## [X.Y.Z] — YYYY-MM-DD
### Added / Changed / Fixed / Removed
- 변경 내용
```

### 3. 전체 페이지 footer 버전 텍스트 업데이트
아래 4개 파일의 footer `vX.Y.Z` 텍스트를 새 버전으로 교체합니다.
- `index.html`
- `claude-web/index.html`
- `claude-desktop/index.html`
- `claude-code/index.html`

### 4. 커밋 메시지 형식
```
vX.Y.Z: 변경 내용 한 줄 요약
```

---

## 버전 번호 결정 방법

- 한 배포에 여러 변경이 있을 때 → **가장 높은 레벨** 기준으로 결정
  - 패치 3개 + 마이너 1개 → 마이너 버전 업
- 동일 날짜에 여러 번 배포 가능 (예: 0.4.1 → 0.4.2 → 0.4.3)
- 마이너를 여러 번 올리지 않음 (0.5.0 → 0.6.0, 0.6.1 아님)

## 버전 표시 위치 요약

| 파일 | 용도 |
|------|------|
| `version.json` | 단일 소스 (버전·날짜·요약) |
| `CHANGELOG.md` | 전체 변경 이력 |
| 각 페이지 footer | 사용자 노출 버전 텍스트 |
