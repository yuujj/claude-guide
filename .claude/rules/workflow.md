# 작업 워크플로우 규칙

## 설계 전 3관점 리뷰 (필수)

새 페이지·섹션·컴포넌트를 설계하거나 기존 구조를 크게 변경하기 전,
**기획자 / UI·UX / 사용자** 관점에서 각각 피드백을 제시한다.

### 형식

```
**기획자 관점**
- 목적·범위가 명확한가? 빈틈이나 중복은 없는가?
- 진입 경로와 이탈 경로가 설계되어 있는가?
- 우선순위와 단계가 합리적인가?

**UI·UX 관점**
- 컴포넌트 선택이 적합한가? (탭 vs 아코디언 vs 카드 등)
- 모바일·접근성·인터랙션 상 문제는 없는가?
- 정보 밀도와 스크롤 부담이 적절한가?

**사용자 관점**
- 초보자와 고급 사용자 모두 원하는 것을 찾을 수 있는가?
- 실제 사용 흐름에서 막히는 지점이 있는가?
- 용어·설명이 대상 독자 수준에 맞는가?
```

### 페르소나 체크 (PRD 기준 — @.claude/prd.md)

3관점 리뷰와 함께 아래 3가지를 확인한다.

- **P1 비개발자**: 기술 용어 장벽 없이 진입 가능한가? 설치·설정 없이 시작할 수 있는 경로가 있는가?
- **P2 개발자**: 스펙·실전 예시를 2클릭 이내에 찾을 수 있는가? 설명 없이 코드 블록으로 충분한가?
- **P3 중간 사용자**: 이진 선택(비개발자/개발자) 없이 자신의 수준에서 자연스럽게 탐색 가능한가?

### 적용 시점

- 새 페이지 초안 작성 전
- 기존 섹션을 대폭 재구성하기 전
- 컴포넌트 구조 변경(탭→아코디언 등) 전

### 완료 후

3관점 리뷰가 끝나고 구현이 완료되면, 자연스럽게 **다음 작업 후보**를 1~2가지 제안한다.
(단, 사용자가 이미 다음 방향을 지시한 경우 생략)
