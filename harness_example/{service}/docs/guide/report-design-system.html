llm-gateway 보고서 시각 표준 · 출처: docs/reports/*.html

이 문서의 <style> 블록을 새 보고서에 복사해 사용하세요

단일 HTML · self-contained 복붙용 CSS 리빙 스타일가이드 시맨틱 컬러 규칙
사용법 — ① 이 파일 <head>의 :root~.ds-* 직전까지 CSS를 복사 → 새 보고서 <style>에 붙임. ② 차트가 필요하면 Chart.js CDN <script> 한 줄 추가. ③ 맨 아래 보일러플레이트 섹션을 시작 골격으로 사용. .ds-* 클래스는 이 가이드 전용이므로 복사 대상이 아닙니다.

3. 헤더 (보고서 머리말)

구성: 제목 + 메타 2~3줄 + 뱃지 행

위 페이지 상단의 다크 그라데이션 영역이 헤더 컴포넌트입니다. 제목(h1) + 메타정보(p, opacity .75) + 상태 뱃지(.badge)로 구성합니다.
<div class="header">
  <h1>보고서 제목</h1>
  <p>대상 · 환경 · 이미지 태그</p>
  <p>작성일: 2026-06-10 | 분석: 방법</p>
  <div class="badges">
    <span class="badge badge-r">핵심 결론</span>
  </div>
</div>
4. 뱃지 & 태그

뱃지 — 헤더 안, 반투명 (어두운 배경용)

badge-r 문제 badge-y 주의 badge-b 정보 badge-g 확인
헤더의 어두운 배경 위에 얹는 요약 라벨. pill 형태, rgba 반투명 배경.

태그 — 표 셀 안, 불투명 (밝은 배경용)

없음   정상   미검증

표 안에서 상태/결과를 표시. 흰 배경 위 솔리드 색. tag-r=문제·부재, tag-g=정상, tag-y=보류·미검증.
5. 알림 박스 — 언제 무엇을 쓰는가

info-box (파랑) — 즉시 적용 가능한 조치 · 안내

  • 중립적 정보, 권고, "이렇게 하면 된다" 류의 안내에 사용

warn-box (주황) — 주의 · 검토 후 적용 권장

  • 리스크가 있거나 코드 변경이 필요한 권장 사항. 부작용 가능성이 있는 조치

confirm-box (초록) — 확정 · 검증 완료 · 안전한 조치

  • 검증이 끝났거나 부작용 없이 적용 가능한 항목, 긍정 결론

card (중립) — 일반 콘텐츠 컨테이너

표·코드·설명 등 의미색이 필요 없는 모든 기본 블록. 가장 많이 쓰는 컨테이너입니다.

# 현재 상태 — 메모리 관리 코드 없음
import gc, ctypes, asyncio

async def periodic_memory_trim():
    """5분마다 GC 및 glibc heap 반환 시도"""
    while True:
        await asyncio.sleep(300)
        gc.collect()
        ctypes.CDLL('libc.so.6').malloc_trim(0)
MISSING ENV MALLOC_ARENA_MAX=2   # 누락 표시용
신택스 span: .c-cmt 주석 · .c-kw 키워드 · .c-str 문자열 · .c-num 숫자. 보조: .file-path(파일 경로 배너), .missing-tag(누락/부재 강조). 인라인은 <code> (밝은 배경, 자홍 텍스트).
9. 차트 (Chart.js 4.x) — 팔레트 & 규칙

시계열 line — 추이 + limit 기준선

실측값(빨강 fill) + 임계선(주황/회색 dashed)

doughnut — 구성 비율

danger vs success 2색 대비

차트 공통 규칙

  • .chart-card(흰 카드) 안에 제목(h3 13px) + 설명(p 11px) + .chart-wrap(height 220px) 구조.
  • 옵션 고정: responsive:true, maintainAspectRatio:false, 범례 position:'bottom', font.size:11.
  • 데이터 색은 시맨틱 팔레트 사용 — 실측/문제=#ff4d4f, 정상=#52c41a, 정보=#1677ff, 보조=#722ed1, 임계선=#fa8c16/회색 dashed.
  • 면적 채움은 rgba(...,.1), 막대는 rgba(...,.6) + 진한 borderColor.
10. 새 보고서 시작 보일러플레이트

아래를 새 .html로 저장 → CSS는 이 파일에서 복사해 <style>에 채우면 시작

<!DOCTYPE html>
<html lang="ko"><head>
<meta charset="UTF-8"/>
<title>○○ 분석 보고서</title>
<!-- 차트 필요 시 -->
<script src="https://cdn.jsdelivr.net/npm/chart.js@4.4.0/dist/chart.umd.min.js"></script>
<style> /* ← 이 파일의 :root ~ .missing-tag 까지 복사 */ </style>
</head><body>

<div class="header">
  <h1>제목</h1>
  <p>대상 · 환경</p><p>작성일 | 방법</p>
  <div class="badges"><span class="badge badge-r">핵심</span></div>
</div>

<div class="container">
  <div class="section-title">핵심 수치</div>
  <div class="stat-row"> ... </div>

  <div class="section-title">본문</div>
  <div class="card"><h3>소제목</h3> ... </div>
</div>
</body></html>
문서 구조 권장 순서: 헤더 → 핵심 수치(stat-row) → 차트 → 본문(원인/분석 card·표) → 권장 조치(info/warn/confirm box) → 중장기(card). 내용 작성 규칙(파일명·섹션·TL;DR)은 guide/report_style_guide.md 참조.
